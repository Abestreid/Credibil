# Поиск — отчёт о переделке

## Что было (проблемы)

| Проблема | Суть |
|----------|------|
| Too many false positives | typoTolerance oneTypo=3 — "Ilan Shor" показывал 5+ нерелевантных результатов |
| Поиск по директорам | searchableAttributes включал director_names/founder_names — имена из разных компаний смешивались |
| Нет пагинации | Всё отдавалось сразу, без offset/page |
| XSS | dangerouslySetInnerHTML в результатах поиска |
| Нет autocomplete | Поле ввода без подсказок |
| Нет разделения типов | Компании и лица смешивались в одном результате |
| IDNO не искал точно | Поиск по 13-значному IDNO через fuzzy → ложные совпадения |

## Что сделано

### Backend

1. **Meilisearch конфигурация** (`meilisearch.py`):
   - typoTolerance: oneTypo=5, twoTypos=8 (вместо 3/6)
   - matchingStrategy: "all" (обязательно все термы совпадают)
   - Убраны director_names/founder_names из searchableAttributes
   - Добавлен entity_type в filterableAttributes

2. **Двухстратегия поиска** (`service.py`):
   - Сначала поиск в Meilisearch
   - Если IDNO (13 цифр) — дополнительный точный lookup в PostgreSQL
   - Результаты объединяются, дубликаты убираются

3. **Классификация совпадений** (`service.py`):
   - EXACT_IDNO, EXACT_NAME, NORMALIZED_NAME, PREFIX, TRANSLITERATION, FUZZY
   - PERSON_EXACT, PERSON_PREFIX, PERSON_RELATED
   - Приоритет сортировки: точные совпадения выше

4. **Пагинация** (серверная):
   - `page` и `page_size` параметры в API
   - `SearchPaginationMeta` в ответе (total_hits, total_pages, has_next, has_prev)

5. **Autocomplete** (`/search/autocomplete`):
   - Минимум 2 символа
   - Возвращает подсказки с entity_type, match_reason

6. **Индексация** (`tasks.py`):
   - `search_reindex_all` теперь использует публичные API endpoints
   - В документы включаются relationship data (директора, учредители, компании человека)
   - Добавлен `entity_type` в каждый документ

7. **Безопасность**:
   - Убран dangerouslySetInnerHTML
   - Highlights отображаются как текст

### Frontend

1. **Types** (`types/index.ts`):
   - SearchResponse теперь имеет `meta: SearchPaginationMeta`
   - SearchHit имеет `entity_type` и `match_reason`

2. **Хуки** (`hooks.ts`):
   - `useCrossSearch` — общий поиск по компаниям и лицам
   - `useSearchParamsState` — URL state (query и page в URL)
   - `useDebouncedValue` — debounce для autocomplete

3. **SearchPage** (`SearchPage.tsx`):
   - Автокомплит с выпадающим списком (debounce 300ms)
   - Пагинация с номерами страниц
   - URL state (?q=Shor&page=2)
   - Раздельные иконки для компаний (🏢) и лиц (👤)
   - Каждый результат ссылается на правильную страницу (/companies/:id или /persons/:id)

## API Endpoints

| Endpoint | Метод | Описание |
|----------|-------|----------|
| `/search` | GET | Общий поиск (компании + лица) |
| `/search/companies` | GET | Только компании |
| `/search/persons` | GET | Только лица |
| `/search/autocomplete` | GET | Подсказки (min 2 символа) |
| `/search/index/{name}` | GET | Количество документов в индексе |
| `/search/reindex` | POST | Переиндексация |
| `/search/health` | GET | Здоровье Meilisearch |

## Параметры поиска

| Параметр | По умолчанию | Описание |
|----------|--------------|----------|
| q | (обязательный) | Поисковый запрос (1-200 символов) |
| page | 1 | Номер страницы |
| page_size | 20 | Результатов на странице (1-100) |
| index | все | Фильтр: companies или persons |
