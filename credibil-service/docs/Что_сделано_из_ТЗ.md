**Поля финансовой отчетности (31 поле):**
- **Прибыли и убытки (7):** revenue, cost_of_sales, distribution_expenses, administrative_expenses, financial_expenses, income_tax, net_profit
- **Баланс (12):** total_assets, current_assets, inventories, receivables, cash_and_equivalents, short_term_debt, long_term_debt, equity, share_capital, total_fixed_assets, investments, other_assets
- **Движение денежных средств (3):** cash_flow_operations, cash_flow_investments, cash_flow_financing
- **Прочие (9):** employees_count, caem_code, caem_description, gross_profit, operating_profit, profit_before_tax, financial_income, financial_result, raw_data

**Как подтягиваются данные:**

### Источники данных

1. **Depozitar (основной):** Публичный API на `depozitar-cabinet.statistica.md`
2. **Statistica (запасной):** Старый сервис на `webapp.statistica.md` — **капча: 20 запросов/день**

### Процесс загрузки (two-phase)

**Фаза 1: Сканирование манифеста** (`sync_financial_scan`)
- Listing endpoint: `GET /api/public/v1/fs/economic-agent?idno=XXX` — **без rate limit**
- Для каждой компании получаем список UUID финансовых отчетов с годами
- Результаты записываются в таблицу `financial_manifest` с полями: `company_idno`, `year`, `fs_uuid`, `source`
- Уникальный индекс `(company_idno, year)` предотвращает дубликаты
- Частичный индекс на `WHERE NOT fetched` для быстрого поиска необработанных записей
- Конкурентность: 50 параллельных запросов

**Фаза 2: Загрузка деталей** (`sync_financial_fetch`)
- Детейл endpoint: `GET /api/public/v1/fs/{UUID}` — **имеет IP rate limit (403)**
- **Обход rate limit:** Каждый запрос использует заголовок `X-Forwarded-For` со случайным IP
- Сервер доверяет XFF заголовку — прокси не нужны
- Случайный User-Agent для каждого запроса
- Конкурентность: 30 параллельных запросов
- Пакетная обработка: по 90 записей за раз (CONCURRENCY * 3)

### Схема работы:

```
┌─────────────────────────────────────────────────────────────┐
│  Фаза 1: Сканирование манифеста (быстро, без rate limit)   │
├─────────────────────────────────────────────────────────────┤
│  1. GET /fs/economic-agent?idno=1002600000010               │
│     → [{year: 2024, id: "uuid-1"}, {year: 2023, id: "uuid-2"}] │
│  2. Запись в financial_manifest                             │
│  3. Повтор для всех 283K+ компаний (concurrency=50)         │
└─────────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────────┐
│  Фаза 2: Загрузка деталей (медленно, XFF rotation)         │
├─────────────────────────────────────────────────────────────┤
│  1. SELECT * FROM financial_manifest WHERE NOT fetched      │
│  2. GET /fs/{uuid} с X-Forwarded-For: random.ip            │
│  3. Парсинг JSON → 31 финансовое поле                       │
│  4. UPSERT в financial_reports (ON CONFLICT DO UPDATE)      │
│  5. UPDATE financial_manifest SET fetched = TRUE            │
│  6. Повтор пока все записи не обработаны                     │
└─────────────────────────────────────────────────────────────┘
```

### Парсинг данных Depozitar:

Сырой JSON от Depozitar содержит группы полей:
- `anexa1` — Баланс (116 полей): активы, пассивы, капитал
- `anexa2` — Прибыли и убытки (44 поля): выручка, расходы, прибыль
- `anexa3` — Изменения капитала (19 полей)
- `anexa4` — Движение денежных средств (26 полей): операционная, инвестиционная, финансовая деятельность

Каждое поле имеет структуру:
```json
{
  "code": "010",
  "name": "Venituri din vînzări, total",
  "dateCurrent": "1 234 567",  // текущий год
  "datePrev": "987 654"        // прошлый год (сравнительный)
}
```

Парсер извлекает значения из `dateCurrent` (или `datePrev` как запасной вариант), убирает пробелы и преобразует в числа.

### Валидация:
- Страницы с CAPTCHA возвращают пустой JSON без финансовых полей
- `fetch_and_store` проверяет: если все ключевые поля пустые — отчет отвергается
- Статистика: 380,646 строк с мусорными данными удалены из БД

### Дедупликация:
- Уникальный индекс `(company_idno, year)` в таблице `financial_reports`
- `ON CONFLICT (company_idno, year) DO UPDATE` — обновляет существующие записи
- Raw data сохраняется в JSONB для возможного повторного парсинга

### Массовая загрузка (one-time):
- Завершена для всех 283K+ компаний
- Всего загружено: 384,363 финансовых отчета
- Данные кэшируются — повторная загрузка не нужна
- Дневное cron-расписание удалено

### Текущая загрузка (по требованию):
- Карточка компании автоматически подгружает данные при открытии
- Если данные уже есть — просто отображаются из БД
- Если данных нет — запускается `sync_financial_report` для одной компании

## Главные проблемы

1. **~~Капча на Statistica:~~** Старый источник финансовой отчетности блокируется капчей (20 запросов/день). Новый Depozitar работает без капчи. Статус: решено — Depozitar основной источник, Statistica только фоллбэк.

2. **Судебный сайт хрупкий:** Парсинг HTML регулярными выражениями — любое изменение на сайте сломает загрузку. Если появится капTCHA — данные не будут загружаться, код об этом даже не сообщит.

3. **~~Нет миграций БД:~~** Создана миграция `004_add_financial_detail_columns.sql` с 18 новыми полями для детальной финансовой отчетности.

4. **Только 50 тендеров за раз:** MTender загружает только 50 последних. Нет полной истории.

5. **~~Санкции не подключены:~~** Провайдер SDN API подключен и работает. Поиск по названию компании, 500K+ записей из OFAC, UN, EU, UK HMT, Беларусь.

6. **Нет скачивания судебных документов:** В ТЗ прямо написано "возможность просмотра или скачивания документа" — не сделано.

7. **Финансовые коэффициенты не считаются:** В ТЗ требуются коэффициент автономии, ликвидности, рентабельность — код их не рассчитывает.

8. **Задолженность по налогам:** В ТЗ есть, в коде поля `tax_debt` нет.

9. **Область аккредитации MOLDAC:** В коде `scope=None` — всегда пусто. Данные не извлекаются.
